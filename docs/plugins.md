# 同步后处理插件协议

后处理插件用于在下载后检查或处理本地文件，按订阅选择启用。普通使用只需登录夸克并添加订阅。插件项目负责自己的安装、运行环境、升级及业务规则。

当前实现协议 1。`src/plugins.cjs` 提供持久化队列、重试和进程调用，订阅卡片显示独立后处理状态。宿主只解释通用协议字段，具体数据格式、内容验证、分析和发布规则由外部插件实现。

## 使用已安装插件

插件提供本地 JSON：`id`、`version`、`command` 参数数组、`timeout_seconds`（默认 60 秒，可设为 1–3600 秒）。`command[0]` 必须是已安装程序的绝对路径，其余元素是参数；宿主无 shell 调用。在订阅卡片点“后处理插件”，选择配置并核对执行命令后启用。配置不会从网盘中自动加载。已有配置按插件 ID 替换；“禁用后处理”停止当前及后续插件执行，保留本地数据。“重试后处理”与重新下载分开。

## 请求、响应与进度

宿主通过 stdin 发送一个 JSON 请求：`protocol_version=1`、`plugin_id`、`plugin_version`、`event_id`、`invocation_id`、Unix 秒 `deadline`、`hook=sync.settled`、`state_dir` 和 `input`（`root`、`job_id`、`source_kind`、`outcome`、`run_id`）。`outcome` 为 success、partial_failure、cancelled、recovered 或 manual；它描述同步状态，不宣称目录已验证。

插件向 stdout 输出一个 JSON 响应，原样返回 `protocol_version` 和 `event_id`，`status` 为 ok、retry、unsupported 或 rejected，可附通用 `message`。额外结果字段原样保存在投递记录中，由插件解释；宿主不会把业务字段映射到订阅状态。输出和诊断各限制 1 MiB，输入不包含账号凭据或签名 URL。进程外运行用于故障隔离，不是权限沙箱；用户应只启用信任的本地程序。

从 1.4.1 起，插件可向 stderr 输出逐行 `PLUGIN_PROGRESS {"event_id":"…","invocation_id":"…","message":"…"}`。
event_id 必须匹配本次请求；invocation_id 可选，提供时也必须匹配。宿主正确处理 UTF-8 跨块、忽略无效行，
单行上限 16 KiB、message 上限 2000 字符。此通道只更新进度，不能替代 stdout 的最终结果。
运行状态、开始时间及最近进度保存到 outbox；卡片优先显示正在运行的任务、阶段进度和耗时，排队数不包含运行项或已拒绝项。

`sync.settled` 是对当前订阅目录重新扫描的通知。同一订阅、目录和插件配置的未开始通知合并为一次扫描；
运行期间有新通知时最多保留一次后续扫描，避免漏掉正在校验时才下载完成的文件。
重启合并旧队列中的重复待处理记录，原记录以内部状态 `superseded` 留存；此状态不是插件响应状态。
手动重试不重新激活全部历史成功任务，不同目录或插件配置不合并。

事件按稳定 ID 与配置摘要保存到用户数据 `plugins/outbox/`，插件状态在 `plugins/state/<job>/<plugin>/`。失败自动退避，终止状态可手动重试；重启扫描覆盖落地后未登记事件的窗口。文件异常或插件失败不回滚已完成下载。协议只包含明确需要的输入，未启用插件不增加外部运行时依赖。

## 传输与插件的职责

`src/model.cjs` 的 `prepareFiles` 对已存在的文件直接跳过，`src/engine.cjs` 组织扫描、分享转存和 rclone 下载。目录会继续递归检查新增成员，但同名文件不会按大小或时间更新。

`engine.cjs` 当前的下载计划数和 rclone 文本日志不能充当某份数据发布已完整的证明。插件需要观察下载落定后的本地文件，并按自己的契约验证。

当前调用边界：

- `engine.cjs` 在本次检查/传输结束或中断时产生 `sync.settled` 通知，包含成功、部分失败或取消状态。新增文件为零时也产生通知，以便检查上轮未齐的数据。
- `plugins.cjs` 持久化待投递事件、执行状态和版本，恢复时补投；插件按输入与规则摘要保证重复执行的结果一致。
- `model.cjs` 负责基础文件规划和路径约束。当前后处理协议提供本地输入目录，不提供额外云端下载或引擎内部对象访问。
- `main.cjs` 管理订阅级插件配置与运行，`preload.cjs` 只暴露有限操作，`ui/app.js` 区分传输状态和后处理状态。插件状态目录位于用户数据目录，独立于程序安装目录和订阅文件目录。

插件应根据本地实际内容检查完整性，不能以下载计划数或截断的日志作为文件清单。进程不可用、超时、异常与协议不兼容都显示在后处理状态中，已完成传输不因插件失败回滚。

## 生命周期与恢复

每次传输结束均使插件可以重新检查自己的待处理对象；恢复扫描覆盖“文件已写入、插件事件尚未登记”的窗口。事件重复不会重复生成同一业务结果。

同步失败时可能已有部分完整文件落地，因此插件可以在该事件中更新进度，但是否可用仍由其内容契约决定。停止下载、停止插件和应用退出分别处理，不把中止解释为成功。重启后持久化任务继续，插件自身对不可变对象可以复用已验证结果。

禁用插件只停止后处理，不删除用户文件。插件应将版本、输入指纹及可用结果写入自己的状态目录；遇到不支持的数据格式时返回 unsupported 和具体原因，并自行保留上一可用结果。

## 通用文件清单示例

例如，一个外部插件可读取 `versions/v2/checksums.json`，检查其中列出的文件及摘要，并在自己的 `state_dir` 保存结果。清单格式和验证规则由该插件定义，宿主不解析这些内容。

默认同步跳过已有同名文件，因此新版本应使用新路径，例如 `versions/v3/checksums.json`。清单先到、引用文件尚未到齐时，插件返回 retry；文件补齐后重新验证，成功才更新自己的可用结果。共享且未变化的文件可由插件复用已有校验结果。

默认同名跳过策略不自动修复损坏文件。用户启用 [修订同步](file-revisions.md) 后，宿主按通用发布记录校验并保留旧件后替换。插件发现其他内容损坏时应说明恢复方法，独立缓存可由插件重建；覆盖用户文件需要单独明确授权。

专用格式、模型、运行环境和部署说明由插件项目维护。插件不可用时，正常下载仍可继续，后处理状态说明依赖未就绪。

## 验收

- 未启用插件时现有追加下载、停止/恢复、分享和更新测试保持通过。
- 成功、零新增、部分失败、取消、崩溃恢复都可以触发对应插件检查，重复投递结果幂等。
- 插件协议/进程错误不会伪装成下载错误，插件输入不包含账号凭据。
- 用通用文件清单示例验证“标记先到、对象后到”；只有内容齐全且正确才可用。
- 新发布有新路径；覆盖旧云端文件不会被错误演示成已同步更新。
- 本地对象损坏时有明确恢复入口，修复前旧已验收快照仍可读；插件不会自动覆盖用户文件。
- 日志区分计划、传输、插件校验和最终可用性；界面显示的状态与持久化记录一致。
