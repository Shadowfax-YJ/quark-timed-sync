# 同步后处理插件接入方案

后处理插件是可选扩展。普通使用仍是 GUI 登录夸克、订阅目录并同步文件，不需要 Python、analysis 或额外安装器。BlackFlow 数据完整性由 analysis 读取时校验；仅需要同步后立即显示领域校验状态时才安装相应插件。

状态：2026-09-11 已实现协议 1。`src/plugins.cjs` 提供持久化队列、重试和进程调用，订阅卡片显示独立后处理状态。

## 使用已安装插件

插件提供本地 JSON：id、version、绝对 command 参数数组、timeout_seconds（1–3600 秒）。在订阅卡片点“后处理插件”，选择配置并核对执行命令后启用。配置不会从网盘中自动加载。已有配置按插件 ID 替换；“禁用后处理”停止当前及后续插件执行，保留本地数据。“重试后处理”与重新下载分开。

请求使用 protocol_version=1、plugin_id/version、event_id、invocation_id、Unix 秒 deadline、hook=sync.settled、state_dir、input（root/job_id/source_kind/outcome/run_id）。outcome 为 success、partial_failure、cancelled、recovered 或 manual；它描述同步状态，不宣称目录已验证。响应必须原样返回协议和事件 ID，状态为 ok/retry/unsupported/rejected。输出和诊断各限制 1 MiB，不转发账号凭据。

事件按稳定 ID 与配置摘要保存到用户数据 `plugins/outbox/`，插件状态在 `plugins/state/<job>/<plugin>/`。失败自动退避，终止状态可手动重试；重启扫描覆盖落地后未登记事件的窗口。文件异常或插件失败不回滚已完成下载。协议只包含明确需要的输入，未启用插件不增加外部运行时依赖。

## 当前约束

`src/model.cjs` 的 `prepareFiles` 对已存在的文件直接跳过，`src/engine.cjs` 组织扫描、分享转存和 rclone 下载。目录会继续递归检查新增成员，但同名文件不会按大小或时间更新。

`engine.cjs` 当前的下载计划数和 rclone 文本日志不能充当某份数据发布已完整的证明。插件需要观察下载落定后的本地文件，并按自己的契约验证。

## 建议接口与改动位置

- 在 `engine.cjs` 增加 `sync.settled` 事件：本次检查/传输已结束或中断，包含成功、部分失败或取消状态。新增文件为零时也产生事件，以便检查上轮未齐的数据。
- 持久化待投递事件、执行状态和版本，插件运行器放在新增的独立模块；恢复时补投，插件按输入与规则摘要幂等。
- `model.cjs` 保持基础文件规划/路径约束；插件需要额外下载时，后续以独立、受限的下载请求 Interface 接入，不能直接修改引擎内部对象。
- `main.cjs` 管理订阅级插件配置与运行，`preload.cjs` 只暴露有限操作，`ui/app.js` 区分传输状态和后处理状态。插件状态目录位于用户数据目录，独立于程序安装目录和订阅文件目录。

插件协议只包含任务 ID、稳定事件 ID、一次检查 ID、来源类型、输入目录、已知文件引用、完成状态、输出状态目录和超时等通用内容。计划下载文件与已核对存在的文件分别描述；文件列表很大时用不可变本地清单引用传递，不依赖截断的日志输出。

推荐首期用受信任本地命令及 JSON 请求/响应；可执行路径和参数来自已安装插件配置，显式启用后运行，不能取自云端文件。使用无 shell 的参数数组调用，传输登录凭据和签名 URL 保持在宿主内部。进程外运行用于故障隔离，不宣称是权限沙箱。

返回区分 `ok`、`retry`、`unsupported`、`rejected`，附插件结果。处理进程不可用、超时、异常与协议不兼容单独呈现。已完成传输不因插件失败回滚，任务 UI 可显示“下载完成；后处理待解决”。

## 生命周期与恢复

每次传输结束均使插件可以重新检查自己的待处理对象；恢复扫描覆盖“文件已写入、插件事件尚未登记”的窗口。事件重复不会重复生成同一业务结果。

同步失败时可能已有部分完整文件落地，因此插件可以在该事件中更新进度，但是否可用仍由其内容契约决定。停止下载、停止插件和应用退出分别处理，不把中止解释为成功。重启后持久化任务继续，插件自身对不可变对象可以复用已验证结果。

禁用插件只停止后处理，不删除用户文件；升级记录插件版本和结果输入指纹。支持范围不兼容时保留上一可用结果并展示待升级原因，不绕过验证。

## 不可变数据集插件示例

具体数据集插件由业务项目维护，例如 `lubiao-analysis` 提供快照验证插件。它读取发布清单和数据块，核验哈希、schema、父发布关系、必要能力及审核状态，更新自己管理的本地快照索引。

云端采用新增的 `releases/<snapshot_id>/manifest.json` 和发布记录。发现新版本依赖新增路径，不能依赖覆盖同名 `latest.json`、READY 或 manifest。完成标记先下载到时仍需等待所有必要对象；本地可用指针是插件状态，不放进云端追加下载目录。

对同名本地损坏文件，宿主当前跳过策略不会自动修复。插件返回明确诊断；修复可以经显式启用的动作下载到插件拥有的新缓存目录，核验后更新本地对象映射。不要静默覆盖用户目录或移除基础“仅追加”约定。

业务插件在 analysis 工具安装时提供自己的运行环境/入口；quark-timed-sync 默认包不捆绑 Python、OCR 模型或某个游戏的 schema。配置缺失时正常下载仍可用，后处理状态说明依赖未就绪。

## 验收

- 未启用插件时现有追加下载、停止/恢复、分享和更新测试保持通过。
- 成功、零新增、部分失败、取消、崩溃恢复都可以触发对应插件检查，重复投递结果幂等。
- 插件协议/进程错误不会伪装成下载错误，插件输入不包含账号凭据。
- 用通用文件清单示例验证“标记先到、对象后到”；只有内容齐全且正确才可用。
- 新发布有新路径；覆盖旧云端文件不会被错误演示成已同步更新。
- 本地对象损坏时有明确恢复入口，修复前旧已验收快照仍可读；插件不会自动覆盖用户文件。
- 日志区分计划、传输、插件校验和最终可用性；界面显示的状态与持久化记录一致。
