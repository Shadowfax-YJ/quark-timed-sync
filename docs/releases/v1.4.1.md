本版修复订阅停在连接阶段，以及后处理正在运行却显示“等待后处理”的问题。

- 后处理卡片优先显示正在运行的任务，展示已运行时间、插件上报的当前阶段和处理数量；排队数量只计算尚未开始的任务。
- 合并同一订阅、目录和配置下重复的待扫描通知，兼容旧版本重启后遗留的重复队列。运行期间有新文件下载完成时，保留一次后续扫描。
- 兼容网盘自动产生的修订记录编号副本，例如 `记录(1).json`。只有原记录存在且完整内容一致时才接受；冲突和缺少原记录时仍报告错误，并显示修订记录检查进度。
- 旧插件配置继续有效。普通同步无需 Python；使用 BlackFlow 快照插件的用户，将原 Python 环境中的 lubiao-pipeline 更新到 [0.3.20 对应提交](https://github.com/Landmark-Achiever/lubiao-analysis/commit/b3e52aaf2e822dbb305faa92b05fc6e967319a25) 后，可以看到分卷校验、解包缓存校验、快照对象和逐局依赖校验等进度。已有解包缓存继续复用。
