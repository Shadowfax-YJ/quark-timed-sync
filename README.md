# 夸克网盘定时同步 — 自动下载新增文件

**开源免费 · 跨平台桌面 · 扫码即用 · 下载组件内置**

**订阅夸克网盘文件夹或分享链接，定时把新增文件下载到电脑。** `quark-timed-sync` 是一个开源桌面同步工具，适合持续更新的资料收集、照片视频归档和分享目录追更，下载时保留原有目录结构。

支持 Windows x64、macOS（Apple 芯片 / Intel）和 Linux（x64 / ARM64）桌面。提供免安装便携包，扫码登录后即可创建订阅，内置运行环境、OpenList 和 rclone，无需自行部署服务。

A free, open-source desktop app for scheduled downloads of new files from Quark Drive folders and shared links. Portable builds for Windows, macOS and Linux, with QR-code login and bundled download tools.

[下载便携版](https://github.com/Shadowfax-YJ/quark-timed-sync/releases/latest) · [快速开始](#快速开始) · [适用场景](#适用场景) · [常见问题](#常见问题)

> **同步方向是“夸克 → 本地”。** 默认只下载本地没有的文件，同名文件跳过，云端删除不会删除本地文件。桌面订阅不自动上传本地文件，也不提供双向同步。

## 核心特点

- **开源免费**：应用源码采用 MIT 许可，可查看、修改和自行构建；本仓库发布的便携包免费提供，无需购买激活码。
- **三平台桌面支持**：Windows x64、macOS Apple 芯片与 Intel、Linux x64 与 ARM64 均提供下载包。
- **扫码登录，界面配置**：使用自己的夸克账号扫码，在界面中选择来源、本地目录和检查间隔，无需手动提取 Cookie 或编辑任务脚本。
- **下载能力已内置**：免安装便携包包含应用运行环境和下载组件，无需另行安装下载器、部署网盘服务或设置系统定时任务；系统要求见 [平台与数据](#平台与数据)。
- **面向通用文件归档**：本人网盘目录、分享目录都能订阅，文档、照片、视频等按原结构保存；默认保留本地已有文件，支持多个独立订阅。

## 快速开始

### 1. 下载并打开

打开 [最新版本下载页](https://github.com/Shadowfax-YJ/quark-timed-sync/releases/latest)，在 **Assets** 中选择文件名带 `portable.zip` 的应用包，完整解压到独立文件夹。GitHub 自动生成的 `Source code` 是源码，不能直接当桌面应用运行。

- **Windows x64**：选择 `Windows-x64-portable.zip` 结尾的包，双击 `夸克网盘定时同步.exe`。
- **Mac**：选择 `macOS-Universal-portable.zip` 结尾的包，Apple 芯片和 Intel 使用同一个包，打开其中的应用。
- **Linux 桌面**：按处理器选择 `Linux-x64-portable.zip` 或 `Linux-ARM64-portable.zip` 结尾的包，运行 `启动夸克网盘定时同步.sh`。

首次运行的系统要求与 macOS 提示见 [平台与数据](#平台与数据)。

### 2. 扫码并创建订阅

1. 使用手机夸克扫描应用显示的二维码，并在手机上确认登录。
2. 点击 **“添加订阅”**，填写一个便于识别的名称，例如“课程资料”。
3. 选择 **“我的网盘文件夹”** 并浏览目录；或选择 **“别人分享的链接”**，粘贴链接、填写提取码（如有），点击“读取分享”并选择目录。下载他人分享需要勾选允许转存，并预留自己的网盘空间。
4. 点击 **“选择本地文件夹”**，设置保存位置和检查间隔。默认每 **60 分钟**检查，可调整为 5～1440 分钟。
5. 点击 **“创建并开始订阅”**。首次检查会下载所选目录中本地尚未存在的文件，以后定期补充新增文件。普通下载使用默认设置即可，无需启用修订同步或配置插件。

### 3. 确认下载结果

例如，订阅云端“课程资料”目录，保存到 `D:\Downloads\课程资料`。云端的 `第一课/讲义.pdf` 会保存为 `D:\Downloads\课程资料\第一课\讲义.pdf`。以后云端新增 `第二课/讲义.pdf`，下一次检查会自动下载。

可在订阅卡片点击 **“立即检查”**，查看状态并打开保存目录。重复检查会跳过已有文件。应用需保持运行；关闭窗口可留在托盘，选择“退出并停止下载”后就不再定时检查。

## 适用场景

- **资料持续更新**：订阅课程、文档或素材目录，定期收取新文件。
- **分享目录追更**：同一个夸克分享链接不断增加内容，自动转存并下载新增文件到电脑。
- **照片与视频归档**：把持续新增的云端文件保存成本地副本，按原目录组织。
- **多个来源分别收集**：为不同网盘目录或分享目录设置独立保存位置和检查间隔。

需要本地与云端双向同步、自动传播删除和重命名，或在无桌面的服务器运行时，当前桌面订阅功能不适用。同名文件自动更新仅支持下文的修订协议，来源发布者需要提供相应记录。

## 默认下载规则

- 只下载本地尚未存在的文件，包括初次订阅时缺少的历史文件。
- 保持目录结构；同名文件无论大小或修改时间是否变化，都会跳过。
- 不覆盖、不删除本地文件，不生成旧版本。
- 重新进入已有子目录，发现后来添加的文件。
- 中途停止不会把未完成内容当作完整文件；下次检查会重试未完成的下载。

在订阅卡片或创建窗口中勾选“按云端修订记录校验并更新同名文件，旧文件留档”，可开启修订同步。
它读取来源根目录的 `.sync-revisions/records`，首次或文件变化时计算本地实际 SHA256，未变化时复用已验证结果；不一致时下载修订对象，校验完成后替换。
从旧版升级后首次检查会建立校验缓存；需要重新读取所有记录和文件时，可点击订阅卡片的“完整校验修订”。
旧包保存在本地 `.sync-recycle/<旧哈希>/<原路径>`，哈希相同则跳过。没有修订记录的文件继续使用默认规则。
云端原件回收、发布命令和记录格式见 [文件修订流程](docs/file-revisions.md)。

本工具通过**轮询**检查更新，不依赖夸克服务端推送。它是非官方客户端，接口可用性及下载速度仍受夸克接口和账号权益影响。

## 常见问题

**云端修改或删除文件，本地会跟着变化吗？**

默认同名文件始终跳过，即使大小或修改时间改变；云端删除不会删除本地文件。云端重命名后的文件会按新路径处理，旧本地文件保留。可选修订同步只处理来源提供了有效修订记录的文件，勾选后也不会自动覆盖其他同名文件。

**下载分享内容为什么还需要自己的夸克账号？**

他人分享的内容会先转存到自己的网盘 `Archive 订阅/订阅-编号` 目录，再下载到本地，需要自己的夸克账号和足够的网盘空间。程序不会自动删除转存文件。属于当前账号的分享会直接读取原文件，不会重复转存。

**文件会真正下载到电脑吗？**

会。下载完成后文件保存在选择的本地目录，可离线打开。应用没有把网盘挂载成虚拟磁盘，也不会定时把本地文件上传回网盘。

**下载速度、会员权益和接口限制会变化吗？**

下载能力受夸克接口、网络和账号权益限制。本工具不提供提速破解，也不能保证上游接口永久不变。登录过期可重新扫码；其他失败可在“日志”中查看原因。

## 托盘、通知与启动

- 关闭窗口后继续在 Windows 系统托盘或 Mac 菜单栏运行。
- “暂停全部”停止当前下载与后续自动检查，暂停状态会保留。
- “立即检查”可在暂停期间手动检查一次。
- “退出并停止下载”结束应用及内置组件；退出后没有独立任务继续检查。
- 下载完成时可发送系统通知。
- 登录电脑时自动启动默认关闭，可在界面中开启或关闭。

移动程序文件夹后，请重新设置开机启动。改变订阅来源或本地目录时，移除该订阅后重新添加即可；移除规则不会删除文件。

## 可选的 GitHub 软件更新

左下角打开“软件更新”，可开启**自动检查并下载更新**，默认关闭。开启后在启动时和每 6 小时检查本仓库的 GitHub Releases，只选择适合当前系统与芯片的正式版。关闭时不自动联网检查，也可以点击“检查并下载”手动更新。

v1.1.0 的 Mac 更新器只识别原来的分架构包，首次升级到 Universal 通用包需从 Releases 手动下载；v1.2.0 起支持通用包的应用内更新。版本变化见 [发布记录](https://github.com/Shadowfax-YJ/quark-timed-sync/releases)。

更新包和对应的 SHA-256 校验文件必须同时存在。下载校验完成后显示“重启更新”；请等待当前订阅下载结束或先暂停，再点击安装。更新助手等程序退出后替换程序，成功启动新版后清理临时恢复副本；替换失败或新版启动即退出时会尝试恢复原程序。配置、登录信息和订阅下载目录不参与替换。

请将便携程序放在独立、当前用户可写的文件夹中，不要将下载文件保存在程序目录内。若目录中存在清单之外的文件、目录不可写、网络失败或校验失败，更新会停止并显示原因。更新期间需要临时保存下载包、解压文件和独立助手，建议预留约 4 GB 空间。Mac 采用本地签名，仍受系统对未公证应用的启动策略限制。

更新来源固定为本项目，不需要 GitHub 登录或访问令牌。实现与验证说明见 [docs/updates.md](docs/updates.md)。

## 日志

左侧“下载订阅”下面的“日志”记录订阅检查、文件下载、分享转存、账号连接、软件更新和应用启停事件。

- 信息、警告、错误、调试四个级别；可按级别、来源、订阅、关键词和时间范围组合筛选。
- 最新记录在前，分页显示；可暂停或恢复界面的实时刷新，不影响后台下载和日志记录。
- 查看和复制单条详情，按当前筛选条件导出全部匹配记录为 TXT 或 JSONL。
- 默认记录信息及以上，保留 14 天、总计最多 25 MB；按日期及每文件 2 MB 自动轮转，超限清理旧日志。可在“日志设置”中调整级别、1～90 天保留期和 1～100 MB 总上限。
- 可打开日志目录或清空记录。日志保存在用户数据目录的 `logs/` 中，重启后保留。清空日志不改变订阅、登录或下载文件。

登录凭据、提取码与链接签名会自动隐藏；详情可能包含文件名和本地路径。开启调试记录可查看内置组件状态与下载进度。新增日志功能无法补回旧版本未记录的事件。

## 平台与数据

Windows 包面向 x64；Mac 提供一个 **macOS-Universal** 通用包，支持 Apple 芯片和 Intel，目标最低系统为 macOS 12。Electron、OpenList 和 rclone 均包含两个原生架构，不依赖 Rosetta。通用 ZIP 在 macOS 15 的 Apple 芯片和 Intel 机器上分别解压运行，并检查所有组件的两个架构、最低系统版本和应用签名；最低系统兼容检查不等同于在 macOS 12 实机测试。

Linux 提供 x64 和 ARM64 两个包，验证配置使用 Ubuntu 22.04 x64 与 Ubuntu 24.04 ARM64。需要图形桌面、GTK 3、NSS、ALSA、GBM、系统密钥环和可用的 Chromium 沙箱环境，不适用于无桌面的服务器。完整解压 ZIP 后运行 `启动夸克网盘定时同步.sh`；桌面环境的压缩工具需保留可执行权限。GNOME 桌面显示托盘可能需要 AppIndicator 支持。Linux 使用 XDG 启动项，凭据保存需要 GNOME Keyring 或 KWallet；程序拒绝使用明文后备密钥保存登录信息。

Linux 原生启动检查在上述 Ubuntu 环境使用 Xvfb 和软件绘制完成。部分发行版限制非特权用户命名空间，需要管理员按发行版规则配置 Chromium 沙箱；程序不会自动关闭沙箱或修改系统安全策略。

Linux 桌面需安装支持中文的字体，例如 Ubuntu 的 `fonts-noto-cjk`，否则中文界面会显示为空框。

Mac 包采用本地签名，尚未经过 Apple Developer ID 公证。若首次打开被拦截，请按照系统提示，在“隐私与安全性”中选择“仍要打开”。

“便携”表示免安装、无需外部运行依赖。配置保存在系统用户数据目录中，更名后沿用原有位置，以保留已有登录和订阅：

- Windows：`%APPDATA%\Archive Subscriptions`
- Mac：`~/Library/Application Support/Archive Subscriptions`
- Linux：`$XDG_CONFIG_HOME/Archive Subscriptions`，通常为 `~/.config/Archive Subscriptions`

登录凭据由系统加密保存；内置网盘服务只监听 `127.0.0.1`，使用随机密码和端口。分发包不包含账号或个人订阅配置，每个人需登录自己的账号。

## 开发与构建

需要 Node.js 24。Mac 构建还需要 Go 1.26.2，以便从未修改的上游源码编译兼容 macOS 12 的 rclone。Linux 构建需要 `zip`、`unzip` 和桌面运行库。

```sh
npm ci
npm run vendor
npm test
npm start
```

生成当前平台的便携 ZIP：

```sh
npm run package
```

输出位于 `out/`，同时生成 SHA-256 校验文件。Mac 的签名和打包需在 Mac 上完成；`vendor` 与 `package` 默认生成 Universal 包。开发时可设置 `ARCHIVE_BUILD_ARCH=arm64` 或 `x64` 单独构建一个架构。

界面与内置组件检查：

```sh
npm run smoke
```

Windows 还可使用 `npm run smoke -- --test-startup`，验证真实系统启动项的开启、界面重载后状态读取和关闭。该测试使用临时身份和数据目录，并在结束时移除测试启动项。

GitHub Actions 构建 Windows x64、macOS Universal、Linux x64、Linux ARM64 四个包，并在 Apple 芯片与 Intel Mac 上验证同一个通用 ZIP。所有平台执行日志界面的筛选、详情、复制、导出、暂停刷新、设置和清空检查。Windows 还运行 `node test/update-runtime.cjs`，使用临时 Electron 副本实测程序替换与重启，不操作真实用户配置。

正式发布使用 Actions 的 **Publish verified release**：填写已成功完成的 **Portable builds** 运行 ID 和对应版本标签（例如 `v1.4.1`），并准备 `docs/releases/v1.4.1.md`。发布任务在 GitHub 内下载该次构建的四个平台产物，核对版本、运行检查和 SHA-256 后上传；八个附件完整且远端校验一致后才公开 Release。重复执行会复用已上传且一致的附件，只补传缺少的文件；遇到冲突会停止。安装包无需经过维护者本地电脑，也不需要重新构建。

图标采用予愿安洁莉娜主题，应用与任务栏使用完整插画，托盘使用简化头像，Mac 菜单栏使用随系统明暗变化的单色版。设计来源和素材导出方法见 [图标说明](assets/branding/README.md)。执行 `npm run icons` 可重新导出图标，不会构建应用安装包。
